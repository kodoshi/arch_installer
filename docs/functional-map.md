## 1. Architecture Overview

DALI is a **declarative, deterministic, idempotent** Arch Linux installer that:

- Reads a single YAML config (`config/config.yaml`) declaring the desired system state
- Assembles one immutable `InstallerConfig` from environment variables over config.yaml (with its encrypted passwords) and, interactively, the TUI, which has the last word; no setting has a code default
- Runs an ordered `PIPELINE` of sections; each enabled section is one executor class
- Supports both **interactive** (curses TUI, every screen starting on the inherited value) and **non-interactive** (environment variables) modes
- Provisions LUKS2-encrypted BTRFS storage with snapper snapshots
- Generates **Unified Kernel Images** (UKIs) signed for Secure Boot via `sbctl`
- Optionally creates a **USB boot drive** with plausible deniability encryption (PDE)
- Optionally migrates data from a previous Arch installation

**Key design patterns:**

- **Ports & Adapters**: `CommandRunner` ABC abstracts all shell commands; `FakeCommandRunner` in tests
- **One frozen config model without defaults**: `InstallerConfig` and every section are `frozen=True` dataclasses with no field defaults; it is built once from the assembled values
- **Explicit value precedence**: values are addressed by dotted setting paths and carry their source; `INHERITANCE_ORDER` in `config/value_precedence.py` states which source wins
- **Type-driven building**: the builder walks the model's type hints, so the model is the schema; unknown keys and wrong types fail with their key path, and every missing setting is reported together
- **Executors**: one class per config section, `Executor(config, runner).execute()`; the orchestrator alone decides whether a section runs
- **Template functions**: file contents are generated by pure functions next to the executor that writes them

**Technology:**

- Python 3.13+, Poetry, PyYAML, cryptography (AES-256-GCM for secrets)
- Dev: pytest, pytest-cov, pytest-xdist, pytest-timeout, ruff, docker (unused)
- 4,906 lines of source code, 6,185 lines of tests, 2,556 lines of shell scripts

## 8. Data Flow Summary

```
env vars ──→ Environment.setting_values() ─────────────────┐ ENVIRONMENT
config.yaml ──→ config_file_setting_values() ──────────────┤ CONFIG_FILE
secrets key ──→ decrypted_credentials() (Argon2id+AES-GCM) ┘
                                    │
                     inherit_setting_values(): INHERITANCE_ORDER = (ENVIRONMENT, CONFIG_FILE)
                                    │  setting path -> SettingValue(value, source)
                     interactive: tui.app.run_tui_setup(inherited) -> choices
                                  apply_tui_choices(): the TUI has the last word
                                    │
                     build_installer_config(): every field required, no code defaults
                                    │
                     validate_for_install() -> InstallerConfig (frozen)
                                    │
                     Installer(config, runner).install()
                        │
                        ├─ for each Section in PIPELINE where section.enabled(config):
                        │     section.executor(config, runner).execute()
                        │        Migration staging, Storage, Pacman mirrors, Packages,
                        │        Migration restore, System, Docker, GPU driver,
                        │        Kernel images, Bootloader, USB boot drive, Snapper,
                        │        Bootable snapshots, Snapshot notifications, Firewall
                        │
                        ├─ _install_utility_scripts()
                        ├─ _write_expected_state() ──→ /etc/dali/expected-state.env (read by verify-install)
                        └─ _write_final_config() ──→ ~/final_config.yaml (exportable_config, no passwords)

All executors use:
  InstallerConfig ── the single, immutable, fully assembled desired state
  CommandRunner ──── run(cmd) / run_as_chroot(cmd) → subprocess (FakeCommandRunner in tests)
```

## 1. Architecture Overview

DALI is a **declarative, deterministic, idempotent** Arch Linux installer that:

- Reads a single YAML config (`config/config.yaml`) declaring the desired system state
- Assembles one immutable `InstallerConfig` from environment variables over config.yaml (with its encrypted passwords) and, interactively, the TUI, which has the last word; no setting has a code default
- Runs the steps of one registry, `INSTALL_STEPS`, in order; each step declares its settings (config key, environment variable, question), its condition and its executor
- Supports both **interactive** (curses TUI, every screen starting on the inherited value) and **non-interactive** (environment variables) modes
- Provisions LUKS2-encrypted BTRFS storage with snapper snapshots
- Generates **Unified Kernel Images** (UKIs) signed for Secure Boot via `sbctl`
- Optionally creates a **USB boot drive** with plausible deniability encryption (PDE)
- Optionally migrates data from a previous Arch installation

**Key design patterns:**

- **Ports & Adapters**: `CommandRunner` ABC abstracts all shell commands; `FakeCommandRunner` in tests
- **One frozen config model without defaults**: `InstallerConfig` and every section are `frozen=True` dataclasses with no field defaults; it is built once from the assembled values
- **Explicit value precedence**: values are addressed by dotted setting paths and carry their source; `INHERITANCE_ORDER` in `config/value_precedence.py` states which source wins
- **Type-driven building**: the builder walks the model's type hints, so the model is the schema; unknown keys and wrong types fail with their key path, and every missing setting is reported together
- **Install step registry**: `InstallStep` to `StepWiring`; the installer, the environment reader and the interactive setup all read it, so a step is wired in one place
- **Executors**: one class per install step, `Executor(config, runner).execute()`; the registry's condition decides whether it runs
- **Front-end port**: the setup session asks through `SetupFrontend`; the curses TUI is one adapter, a GUI would be another
- **Template functions**: file contents are generated by pure functions next to the executor that writes them

**Technology:**

- Python 3.13+, Poetry, PyYAML, cryptography (AES-256-GCM for secrets)
- Dev: pytest, pytest-cov, pytest-xdist, pytest-timeout, ruff, docker (unused)
- 5,691 lines of source code, 7,101 lines of tests, 2,622 lines of shell scripts

## 5. Shell Scripts

### `scripts/dotfiles-sync.sh` (921 lines)

Standalone dotfiles synchronization tool with KeePassXC SSH agent integration.

**Commands:** `init <repo-url>`, `push [--dry-run]`, `pull [--dry-run] [--force]`, `status`, `diff`

**Key features:**

- KeePassXC SSH agent detection and desktop notifications (notify-send/kdialog)
- File mapping from config YAML or defaults (21 default mappings for common dotfiles)
- Sensitive file protection during pull (pacman.conf, makepkg.conf, etc. skip by default)
- Auto version tracking (semver in `.dotfiles-version`)
- Lock file management to prevent concurrent operations
- Git server auto-detection (GitHub/GitLab/Gitea/Bitbucket)

### `scripts/manage_snapshot_entries.sh` (687 lines)

BTRFS snapshot UKI manager for systemd-boot (Secure Boot compatible).

**Commands:** `refresh [N]`, `list`, `cleanup`, `space`

**Key features:**

- Detects running kernel and installed kernels
- Builds per-snapshot cmdline with LUKS params
- Creates UKIs via `ukify` (preferred) or `objcopy` (fallback)
- Signs with `sbctl` for Secure Boot
- Makes read-only snapshots writable for booting
- Custom os-release per snapshot with timestamp and kernel name
- Desktop notifications on success/failure

### `scripts/verify_install.sh` (1014 lines)

Post-installation verification tool.

**Sections verified:** Secure Boot, UKI, bootloader (systemd-boot), LUKS encryption, BTRFS (subvolumes/mount options/NoCoW), swap, system config (hostname/TZ/locale/keymap/user), network, services (including every `packages.display_manager`), firewall (UFW), kernel hardening params, GPU, fstab, essential packages.

Expected values come from `/etc/dali/expected-state.env`, written by the installer (`expected_state.py`) and sourced only when root owns it and nobody else can write it; without it the config-dependent checks are skipped with a warning. Has `--fix` mode for auto-remediation, `--verbose` mode and `--expected-state FILE`.

## 8. Data Flow Summary

```
env vars ──→ Environment.setting_values(environment_variable_paths()) ──┐ ENVIRONMENT
config.yaml ──→ config_file_setting_values() ───────────────────────────┤ CONFIG_FILE
secrets key ──→ decrypted_credentials() (Argon2id + AES-GCM) ───────────┘
                                    │
                     inherit_setting_values(): INHERITANCE_ORDER = (ENVIRONMENT, CONFIG_FILE)
                                    │  setting path -> SettingValue(value, source)
                     interactive: setup.session.run_setup(inherited, CursesFrontend, machine)
                                  walks INSTALL_STEPS, asks each StepSetting's question
                                  apply_tui_choices(): the answers win
                                    │
                     build_installer_config(): every field required, no code defaults
                                    │
                     validate_for_install() -> InstallerConfig (frozen)
                                    │
                     Installer(config, runner).install()
                        │
                        ├─ for each step in INSTALL_STEPS whose wiring.enabled(value) holds:
                        │     wiring.executor(config, runner).execute()
                        │        Migration staging, USB boot drive, Storage, Pacman mirrors,
                        │        Packages, Migration restore, System, Docker, GPU driver,
                        │        Kernel images, Bootloader, Recovery system, Snapper,
                        │        Bootable snapshots, Snapshot notifications, Firewall,
                        │        USB boot safeguards
                        │
                        ├─ _install_utility_scripts()
                        ├─ _write_expected_state() ──→ /etc/dali/expected-state.env (read by verify-install)
                        └─ _write_final_config() ──→ ~/final_config.yaml (exportable_config, no passwords)

All executors use:
  InstallerConfig ── the single, immutable, fully assembled desired state
  CommandRunner ──── run(cmd) / run_as_chroot(cmd) → subprocess (FakeCommandRunner in tests)
```
